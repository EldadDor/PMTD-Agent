## Approved V1 schema

UUIDs are generated by the application; no extension or server UUID function.
Timestamps use `timestamptz`; calendar rating dates remain `date`. A namespace
distinguishes TMDB movie and TV IDs, which may have the same numeric value.

```sql
CREATE TABLE catalog_title (
    id uuid PRIMARY KEY,
    display_title text NOT NULL CHECK (length(trim(display_title)) > 0),
    kind text NOT NULL CHECK (kind IN ('movie', 'series', 'other', 'unknown')),
    release_year integer CHECK (release_year BETWEEN 1800 AND 9999),
    created_at timestamptz NOT NULL,
    updated_at timestamptz NOT NULL
);

CREATE TABLE title_external_id (
    namespace text NOT NULL CHECK (namespace IN (
        'imdb_title', 'tmdb_movie', 'tmdb_tv', 'tvmaze_show'
    )),
    external_id text NOT NULL CHECK (length(trim(external_id)) > 0),
    title_id uuid NOT NULL REFERENCES catalog_title(id),
    observed_from text NOT NULL CHECK (length(trim(observed_from)) > 0),
    first_seen_at timestamptz NOT NULL,
    last_seen_at timestamptz NOT NULL,
    PRIMARY KEY (namespace, external_id),
    UNIQUE (title_id, namespace),
    CHECK (namespace <> 'imdb_title' OR external_id ~ '^tt[0-9]+$')
);
CREATE INDEX title_external_id_title_idx ON title_external_id(title_id);

CREATE TABLE imdb_import_batch (
    id uuid PRIMARY KEY,
    content_sha256 text NOT NULL UNIQUE CHECK (content_sha256 ~ '^[0-9a-f]{64}$'),
    imported_at timestamptz NOT NULL,
    total_rows integer NOT NULL CHECK (total_rows >= 0),
    inserted_rows integer NOT NULL CHECK (inserted_rows >= 0),
    updated_rows integer NOT NULL CHECK (updated_rows >= 0),
    unchanged_rows integer NOT NULL CHECK (unchanged_rows >= 0),
    invalid_rows integer NOT NULL CHECK (invalid_rows >= 0),
    CHECK (total_rows = inserted_rows + updated_rows + unchanged_rows + invalid_rows)
);

CREATE TABLE imported_rating (
    imdb_id text PRIMARY KEY CHECK (imdb_id ~ '^tt[0-9]+$'),
    namespace text NOT NULL DEFAULT 'imdb_title' CHECK (namespace = 'imdb_title'),
    rating smallint NOT NULL CHECK (rating BETWEEN 1 AND 10),
    rated_on date,
    first_import_id uuid NOT NULL REFERENCES imdb_import_batch(id),
    last_import_id uuid NOT NULL REFERENCES imdb_import_batch(id),
    last_source_row integer NOT NULL CHECK (last_source_row > 0),
    updated_at timestamptz NOT NULL,
    FOREIGN KEY (namespace, imdb_id) REFERENCES title_external_id(namespace, external_id)
);
```

This initial single-user slice stores no filename/path, raw CSV, tokens or free
text. Missing ratings are invalid import rows rather than zero. `unknown`/`other`
avoid inventing a movie/series classification for unsupported or absent CSV types.
Conflicting trusted IDs are rejected/reported, never fuzzy-merged. Exact import
header mapping, duplicate-row policy and older-vs-newer export update policy will
be reviewed against an actual private export in P1B-01 before importer work.

## Transactions and later entities

- An import transaction records its batch, title/ID upserts and valid ratings
  atomically. A failed transaction leaves no successful batch marker. Concurrent
  imports with the same digest converge through the unique constraint; the losing
  transaction rolls back and reads the committed result. A known digest is a no-op.
- Serialize imports initially; conflicting trusted identifiers cause an explicit
  conflict instead of reassignment. Metadata and field-level provenance from
  discovery will need a separate reviewed migration, not blind title overwrites.
- Release events/cursors follow in P1C: source event keys, distinct discovery and
  release/season/episode facts, unknown dates, region and provenance. Commit each
  bounded page and its checkpoint together; never advance after failed writes.
- Recommendation/outbox design follows the delivery policy decision: unique
  intent key, attempt/receipt tracking, pending/in-flight/sent/failed/uncertain
  states. Never auto-resend an uncertain attempt before the user chooses policy.
- Feedback/state/preferences remain deferred per the user. Later design must
  deduplicate provider event IDs, authenticate users/callbacks and atomically write
  feedback plus state. One rejection must not become a blanket genre dislike.
